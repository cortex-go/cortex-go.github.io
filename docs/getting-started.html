Getting started

Install a release or build Cortex with Go, make sure opencode is available in the same environment, then start Cortex. By default its workspace root is your home directory; use --root when you want to confine it more tightly.

Install a release

$ curl -fsSL https://cortex-go.github.io/install.sh | sh

Or, if you use Go tooling:

$ go install github.com/cortex-go/cortex/cmd/cortex@latest

Build from source

Cortex uses Nift for its application frontend. The repository keeps frontend source in content/ and templates/; public/ is generated and embedded into the Go binary. After changing frontend source, build Nift before compiling Cortex.

nift build
nift status
go test ./...
go build -o cortex ./cmd/cortex
./cortex
# optional tighter boundary:
./cortex --root ~/Repositories

Install Cortex

If Go is installed, the simplest cross-platform installation is:

go install github.com/cortex-go/cortex/cmd/cortex@latest

Linux and macOS can also install the latest prebuilt GitHub release:

curl -fsSL https://cortex-go.github.io/install.sh | sh

The install.sh script installs to ~/.local/bin by default. GitHub Releases also contain Windows, Linux and macOS binaries.

Secure Cortex on first load

On the first browser visit, Cortex asks you to create the instance password before exposing workspaces, provider settings or the coding-agent APIs. You do not need to create an account from the terminal. Later visits require that password. Optional TOTP two-factor authentication and Google sign-in can then be configured under Settings → Security.

Configure the first agent

Open Settings, choose OpenCode Zen, paste your API key, and save it. Cortex stores the key server-side and never sends it back to the browser.

Run a task

Open Cortex at 127.0.0.1:7331. A directory chooser opens automatically for a new session. Browse under the configured root and choose a workspace without typing a filesystem path. Click a directory once to enter it, use the Up button to go back, then choose Use this directory when you are at the workspace you want. Describe the task, press Enter to run, and use Shift+Enter for a newline.

Work in parallel

Use the ＋ menu to start a fresh session in the current workspace or choose a new workspace. Each tab continues its own OpenCode conversation, so one browser window can supervise several independent development tasks. Recently closed sessions are available from the same menu for restoration.
