Coding agent

Cortex v0.1 uses OpenCode as the coding-agent engine and DeepSeek V4 Flash through OpenCode Zen as its first dogfood model path.

Focused session surface

The main Cortex view follows the compact agent-card layout proven in Warden: agent identity and state at the top, a dedicated workspace strip, the execution transcript, then the composer. Session tabs remain above it for parallel work.

Visible execution

Assistant text, tool calls, commands, completion states and errors stream into the session. Whitespace-only events are discarded, and tool status is highlighted so long autonomous runs remain scannable. Assistant responses receive conservative Markdown highlighting for headings, emphasis, inline code, fenced code blocks, lists, blockquotes and links. Headings keep the normal transcript font size, while Markdown emphasis keeps its literal markers and uses colour rather than removing them. Tool traces remain verbatim, and Copy session still copies the original Markdown/text rather than rendered HTML.

Example session

A Cortex session keeps the agent's tool trace visible while it works:

cortex · ~/Repositories/project
Agent Read HANDOVER.md and implement the task.
↳ read · completed
↳ edit · completed
↳ bash · completed go test ./...
Done Tests pass. Workspace updated.

Recovery

Some headless OpenCode runs can complete without emitting the final assistant text or final usage event to stdout. Cortex records the session ID and exports the isolated session after every successful run, using the saved step-finish data to recover missing responses and token/cost accounting.

Authentication boundary

The coding-agent, workspace and provider APIs require an authenticated Cortex session. Authentication is enforced by the backend rather than merely hiding the interface in the browser.

Authority

The agent can edit files and run commands with the operating-system authority of the Cortex process. The configured workspace root limits which directory can be selected through Cortex, but this remains a high-authority development tool.

Multiple sessions

Each Cortex tab is an independent coding session and can point at a different workspace. Sessions remember their workspace, conversation and OpenCode session identity in the browser, while OpenCode's per-session data is isolated on the Cortex server so follow-up prompts can continue the same agent conversation.

Agent-first interface

Cortex intentionally does not embed a code editor. Choose a directory in the browser, give the agent a task, inspect its tool activity and open another tab when you want a parallel session or another workspace.

Session lifecycle

The ＋ menu separates New session from New workspace. New session starts a fresh agent conversation in the current workspace; New workspace opens the directory chooser for an independent workspace. Closed sessions are retained locally and can be restored from the same menu, including their workspace, transcript and OpenCode session identity.

Resizable composer

The prompt box itself is fixed rather than using the browser's native textarea resize handle. Grab the top border of the composer and drag it to expand or shrink the entire prompt section; the transcript gives up or regains space with it. Double-click the divider to restore the default height.
