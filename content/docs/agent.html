Coding agent

Cortex v0.1 uses OpenCode as the coding-agent engine and DeepSeek V4 Flash through OpenCode Zen as its first dogfood model path.

Focused session surface

The main Cortex view follows the compact agent-card layout proven in Warden: agent identity and state at the top, a dedicated workspace strip, the execution transcript, then the composer. Session tabs remain above it for parallel work.

Visible execution

Assistant text, tool calls, commands, completion states and errors stream into the session. Whitespace-only events are discarded, and tool status is highlighted so long autonomous runs remain scannable.

Recovery

Some headless OpenCode runs can complete without emitting the final assistant text or final usage event to stdout. Cortex records the session ID and exports the isolated session after every successful run, using the saved step-finish data to recover missing responses and token/cost accounting.

Authority

The agent can edit files and run commands with the operating-system authority of the Cortex process. The configured workspace root limits which directory can be selected through Cortex, but this remains a high-authority development tool.

Multiple sessions

Each Cortex tab is an independent coding session and can point at a different workspace. Sessions remember their workspace, conversation and OpenCode session identity in the browser, while OpenCode's per-session data is isolated on the Cortex server so follow-up prompts can continue the same agent conversation.

Agent-first interface

Cortex intentionally does not embed a code editor. Choose a directory in the browser, give the agent a task, inspect its tool activity and open another tab when you want a parallel session or another workspace.
